# AdKiller 审核顺序

AdKiller 是独立广告评分服务，不使用 Prompt 编辑器中的规则。它只对现有 `enabled_chat_ids` 中且已启用的群生效；不会自动添加群或更改现有分段、密钥和文字超时。

- 文字与 AI 简介：先按现有顺序执行完整模型链，模型成功（包括正常与广告判定）就结束；只有模型链穷尽或无可用模型时，才使用 AdKiller 文字评分。分段为 `none` 时表示未命中；消息命中按分段执行，简介命中仍按原简介违规流程处理。评分失败保留原有审核失败策略。关键词简介模式仍是关键词模式。
- 图片：在 AI 暂停、信任和配额等安全检查后，使用已下载的静态图片字节和可选 caption 先做 AdKiller OCR 评分。命中动作则执行一次；未命中、无 OCR 且无 caption、请求失败或不支持的图片继续走原视觉模型链。OCR 只评估图片文字和 caption，不能替代对画面的视觉审核。动画/视频继续原有路径，静态贴纸或其现有缩略图按已下载图片处理。
- 图片请求使用独立最多 12 秒预算，文字仍使用现有 `timeout_ms`；上游返回 429（包括 OCR 繁忙）不会紧循环重试。允许 JPEG、PNG、WebP，图片最大 5 MiB；现有 Telegram 视觉下载限制更严格时仍按原限制处理。图片费用为每次 5 个 RPM token、1 个 QPS token。
- 历史 `on_failure=skip` 配置会保留但不再阻止视觉模型；无需改配置或迁移。模型正常跳过（暂停、配额等）不是模型失败，不启用文字兜底。取消不延长；模型链真正穷尽且本地审核期限到期时，仅在调用方仍存活时使用独立有界兜底预算，并重新检查暂停、冻结、群授权和豁免。

决策来源分别标为 `adkiller-text-fallback`、`adkiller-image-ocr` 或模型标识，AdKiller 不标记模型 Prompt 版本。常规日志不包含图片、OCR 全文或 caption。测试和部署不得发送真实群隐私内容给外部测试服务。
